# v0.7.3 — installed-version release notes

## Goal

Make the installed version’s release notes available without a newer update or network access.

## Scope and decisions

- Add **Settings → What’s new** beside the installed version.
- Bundle `app/release-notes.md` with the renderer; use the same file for GitHub and updater release notes.
- Reuse the existing sanitized Markdown renderer and compact dialog styles.
- Keep installed notes independent of update checking, downloading, and installation state.
- Preserve modal focus, Escape behavior, and remote-key isolation.
- Do not change pairing, credential storage, dependencies, or update signature verification.

## Acceptance evidence

- [x] Installed notes open after the browser smoke server is stopped, without an update check.
- [x] Markdown headings, lists, and emphasis render in the installed-notes view.
- [x] Tab focus stays in the dialog; Escape restores focus to What’s new; arrow keys do not reach the remote.
- [x] Failed background checks and completed background downloads do not replace installed notes.
- [x] Switching to the updater closes the installed-notes dialog and preserves the update resource.
- [x] The release workflow emits the bundled notes file and fails when it is missing.
- [x] Typecheck, renderer build, lint, 133 behavioral tests, and PR #77 CI pass.

Browser smoke verification does not establish a native installed-app interaction. Verify that surface after installing the release.
